## Decision

Wan 2.2 A14B is a two-expert denoising family. High-noise and low-noise models are ordered semantic roles, not interchangeable precision shards. T2V and I2V use operation-specific expert pairs.

Engine currently implements only I2V through an exact five-resource stored-FP8 closure. The loader and typed component contract are substantial. The next work is not another quantization format: first make the filtered support directory reproducibly acquirable, then complete target-workstation acceptance.

First/last-frame is a separate official graph and should not be inferred from ordinary I2V.

## Exact official I2V topology

The pinned I2V example uses:

- `wan2.2_i2v_high_noise_14B_fp8_scaled.safetensors`;
- `wan2.2_i2v_low_noise_14B_fp8_scaled.safetensors`;
- scaled-FP8 UMT5-XXL;
- `wan_2.1_vae.safetensors`;
- 20 steps split after step 10;
- CFG 3.5 for each expert;
- Euler sampler, `simple` scheduler, and model-sampling shift 8.

The example repository is pinned above. Do not replace its revision with a short prefix plus a guessed suffix. The source conflict between 16 fps in older example output nodes and 24 fps in Wan documentation remains explicit. Engine currently chooses 24 fps; a comparison must record playback rate rather than silently normalizing it.

Proof level: runtime/structure exists, but automatic installation and the full output/cold/warm/cancel/reuse matrix are incomplete.

## Loader and runtime implementation packet

No broad loader rewrite is needed. Reuse the current typed recipe, stored adapter, UMT5 adapter, Wan VAE adapter, conditioning/orchestration modules, runtime manager, and poison/ejection behavior.

The acquisition packet must enumerate every file in the 529,069,044-byte support directory with immutable source revision, relative path, byte count, and hash. The installer must prove it fetched exactly that filtered set and no transformer/text-encoder weights. If Hugging Face snapshot filtering cannot express a complete immutable manifest, use explicit file resources or a first-party packaged support artifact.

Runtime acceptance must prove:

- expert roles cannot be swapped;
- high expert is released before low expert residency where designed;
- UMT5/source image caches are keyed by exact identities and preprocessing;
- stored FP8 tensors remain quantized and dispatch through the intended backend;
- no simultaneous hidden dense copy or dual-expert residency;
- cancellation at load, each denoising stage, transition, VAE decode, and export yields a clean next run.

## Hardware and scientific acceptance

Fixed I2V case: one source image, seed `43301611940728`, 832 by 480, 81 frames, 24 fps, 20 steps, split 10/10, CFG 3.5/3.5, shift 8, Euler/simple.

Add 720p-class and 121-frame diagnostics only after the fixed case passes. Corpus covers people, animals, vehicles, products, landscapes, illustration, camera motion, high/low motion, text/signage, occlusion, source identity, anatomy, temporal texture, and prompt-image balance.

Required scenarios: runtime-cold plus three changed-seed warm runs; same prompt/source cache hit and changed-source invalidation; FP8 I2V to Wan 5B to FP8 I2V switching; cancellation in every phase; malformed each-resource case; explicit teardown. Record stage load/ejection, dispatch counts, VRAM/RAM/Windows commit, disk reads, transfer, output hash, and creator review.

A dense BF16 reference may run on Vast. Retain exact operation settings; do not shrink or quantize the Reference and call it equivalent.

## Ordered bounded slices

1. **Next: exact support-directory acquisition manifest.** Acquisition only. Tests prove exact file closure, no duplicate download, no unrelated weights, and deterministic lock.
2. **Target RTX 5080 acceptance.** Current recipe only; cold/warm/cancel/recovery, expert residency, cache invalidation, provenance, creator corpus.
3. **Dense BF16 reference.** Adequate hardware, identical settings, paired output review.
4. **Promotion decision.** Recommended only after automatic install, accepted output, and lifecycle health.
5. **Separate T2V or FLF only on explicit demand.** Use operation-specific expert pairs/graphs; never reuse I2V contracts.

Stop on an unreproducible support file, role ambiguity, native fallback, simultaneous expert residency beyond policy, or poisoned recovery.
