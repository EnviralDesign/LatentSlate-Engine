## Decision and next slice

Wan 2.2 A14B is a two-expert model family. T2V and I2V use operation-specific high-noise and low-noise experts; first/last-frame is another topology. Engine currently has an exact typed **I2V** five-resource stored-FP8 path. The next slice is not another loader: finish target-hardware acceptance and make the filtered support resource reproducibly acquirable. Only then consider T2V or first/last-frame.

## Loader/runtime packet at audited Engine commit

Reuse current `wan22_recipe.py`, Wan I2V adapter/materializer/runtime modules, `stored_quant.py`, `runtime/kit.py`, manager/residency policy, and native tool. Existing policy stages high and low experts, validates exact components, and ejects poisoned state after cancellation/failure.

Acceptance must prove:

- exact component signatures before/after load;
- no expert swap, no simultaneous accidental duplicate, and correct 10/10 boundary;
- scaled-FP8 tensors remain stored/quantized through module assignment and intended backend dispatch;
- UMT5/source-image conditioning cache keys include prompt, image content hash, preprocessing, canvas, and exact resources;
- high expert is released/ejected before low residency; transformer state released before VAE decode;
- cancellation at either expert or transition poisons/ejects both stage states.

The support resource is the operational blocker. Author an exact file-by-file manifest/allow-pattern with immutable identities or publish a first-party support-only artifact; never download a full repository and discard untracked weights at runtime.

## Hardware/scientific acceptance packet

Fixed I2V case: pinned source image, seed `43301611940728`, 832×480, 81 frames, 24 fps, 20 steps, 10/10 split, CFG 3.5, Euler/simple, shift 8. Add 121-frame and 720p-class cases only after baseline stability.

Scenarios: cold + three warm; same prompt/image cache hit; changed image invalidation; cancellation during source decode/UMT5/high load/high denoise/transition/low load/low denoise/VAE/export; A→B→A with another accepted recipe; malformed/missing expert and stage-role swap; explicit teardown. Assertions: five exact resource identities, stage split and dispatch counts, expert residency/ejection, image preprocessing, fps/frame count, cache state, output hash. External device sampling is approximate.

Quality corpus: people/faces/full body, animals, vehicles/products, landscapes/illustration, static/pan/dolly/orbit/handheld, low/high motion, text/signage, occlusion/reappearance. Review source fidelity, identity, anatomy, motion smoothness, temporal texture, and first-frame reconstruction.

## Ordered bounded slices

1. **Next — exact support acquisition.** No runtime behavior change. Produce safe immutable support file closure and tests for completeness/no extra weights. Stop if no reproducible authoritative source can be declared.
2. **I2V target-hardware acceptance.** Existing recipe only; cold/warm/cancel/recovery/stage provenance/creator review. Likely files: hardware-study script plus defects surfaced in current Wan runtime/tests. Out of scope: T2V/FLF/new quant formats.
3. **Dense BF16 cloud Reference.** Same I2V settings on adequate hardware; retain exact source-of-truth closure.
4. **T2V only after I2V promotion.** Distinct experts/resources/tool/request and fixed official workflow. Do not reuse I2V artifacts.
5. **FLF2V after T2V or explicit demand.** Two endpoint inputs, endpoint fidelity corpus, distinct closure/topology.
